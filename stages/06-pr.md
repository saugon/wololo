# Stage 6: pr

Comes after gate_b.

**When `config.pr.enabled` is false:**
1. Enter the stage.
2. Complete it with `note: "PR disabled; branch <branch> kept locally"`.
3. Sign what is unsigned (step 2), then finish as **When `config.pr.enabled` is false** says, after step 9.

1. `event stage.entered {stage: "pr"}`.

**When `config.adapters.pr` exists and `replaces` the stage,** the project's tool publishes: sign nothing and push nothing yourself. Call `mcp__wololo__run_adapter {point: "pr"}`, record `pr.opened` from its answer when it names a PR, then, while its answer says the tool goes on by itself, call `mcp__wololo__run_adapter {point: "poll"}` in later turns until it reports a state that waits on a reviewer or a merger, or a final one. Then write the summary (step 8) and go into review (step 9); when the tool reports the PR merged, record `run.finished {outcome: "done"}` instead. Otherwise:
2. **Sign what is unsigned.** When the run recorded any `signing.deferred` (`counts.unsigned` in `get` scope `run`):
   1. Re-sign every commit of the branch in one pass: `git rebase --exec "git commit --amend --no-edit -S" origin/<base>`. Use the local `<base>` when there is no `origin/<base>`.
   2. When it succeeds, record `signing.done {count}`.
   3. When signing fails again:
      1. `git rebase --abort`.
      2. Record `blocked {reason: "the commits need your signature: unlock 1Password (or your signing key)"}`.
      3. Ask with AskUserQuestion: **Ya desbloqueé, reintentar (Recomendado)** / **Cancelar el run**.
      4. On retry, record `unblocked` and repeat this step.

      Never push unsigned commits, and never turn signing off for the push.
3. **Push:** `git push -u origin <branch>`, exactly. The mod refuses any other push.
4. **Write `run_dir/pr-body.md`** in `config.languages.pr`:
   - **Summary**;
   - **Changes**, item by item;
   - **Acceptance scenarios covered**;
   - **Tests**: the commands and their results;
   - **Screenshots**: their local paths and captions, saying they are local files;
   - **Assumptions and decisions**;
   - **Risks and notes**;
   - `Closes #<n>`, when the source is an issue.

   Also follow the repository's PR template (`.github/pull_request_template.md`) and its CLAUDE.md rules for PRs. No attribution lines.
5. **Open it** with `mcp__wololo__publish {kind: "pr_create", title, base, head: <branch>, draft: config.pr.draft, body_file: run_dir/pr-body.md}`. The title follows the repository's style. When the body changes after the PR is open, update `pr-body.md` and send it with `publish {kind: "pr_body", number, body_file}`.
   - When the body does not fit, write `run_dir/pr-summary.md` (summary, changes, tests, `Closes #n`) and call again with `summary_file`.
   - Then record `pr.opened {url, number, draft}`.
6. **CI**, when `config.pr.wait_ci` is set:
   1. `ci.updated {state: "pending"}`.
   2. Run `gh pr checks <number> --watch --fail-fast` as a background Bash command, then end the turn. The mod shows `waiting_ci`.
   3. When its notification arrives:
      - **Green**: `ci.updated {state: "passing"}`.
      - **Red**:
        1. `ci.updated {state: "failing"}`.
        2. Read `gh run view <id> --log-failed`.
        3. Fix it through the implement loop (implementer, verifier, commit).
        4. Push, and watch again.
      - The fixes are limited to `budgets.ci_fix_attempts`. Past that, record `blocked` and ask; in `full`, finish with `outcome: "failed"` and a summary of what still fails.
   4. A repository with no checks counts as passing, with a note.
   5. A suite left to CI (`config.tests.suite_runs` or `e2e_runs` set to `ci`) is proven here: a red check in it is fixed like any other.
7. **Ready:** when the PR is a draft and CI is green, `mcp__wololo__publish {kind: "pr_ready", number}`: it runs `gh pr ready` and records `pr.ready` itself. Never `gh pr ready` from the shell, which the permission classifier can refuse.
8. **Summary.** Write `run_dir/summary.md`:
   - what was delivered;
   - the PR link;
   - the assumptions and decisions;
   - the open items;
   - the time per stage, from `get` scope `run`.
9. **Into review.** `event review.waiting {}`. The run stays open, in review: it is not done until the PR merges.
   - Keep the worktree: the review may ask for changes.
   - The last message: five lines at most, with the PR link, the path to `summary.md`, and that the run ends when the PR merges (or with `/wololo done`).

**When `config.pr.enabled` is false,** there is no PR to review: write the summary, record `stage.completed {stage: "pr", note}` and `event run.finished {outcome: "done", summary: "<one line>"}`.

## In review

The run waits on the PR's reviewers. Nothing of its own goes on, so it shows as **En revisión**, never as orphaned, and the session can be closed. The mod asks GitHub about the PR every few minutes while a session holds the run:

- **Merged:** the mod records `pr.merged` and `run.finished {outcome: "done"}`. Nothing for you to do.
- **Closed without merging:** the mod records `pr.closed`, which waits on the person, and asks you to ask them. Ask with AskUserQuestion (header **PR cerrado**): **Cancelar el run** / **Dejarlo en revisión** (it may be reopened). On cancel, `event run.finished {outcome: "cancelled", summary}`.
- **Reopened:** the mod takes it back to review.

When the person asks for changes on the PR (review comments, conflicts with the base, a red CI), do them as part of the run:

1. `event doing {text}` saying what the review asked for. The run shows as working while you do it.
2. Each change goes through the implement loop: implementer, verifier, reviewer, commit, as in `stages/04-implement.md`, with the items numbered after the plan's.
3. Push exactly as in step 3, and watch CI as in step 6.
4. Update `pr-body.md` and send it with `publish {kind: "pr_body", number, body_file}` when the change alters what the PR says; answer review comments with `publish {kind: "pr_comment", number, body_file}`.
5. When it is pushed and green, the run is back in review by itself: nothing to record.

`/wololo done` ends the run as done without a merge, when the person decides it is.
