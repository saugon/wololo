# Stage 6: pr

Comes after gate_b.

**When `config.pr.enabled` is false:**
1. Enter the stage.
2. Complete it with `note: "PR disabled; branch <branch> kept locally"`.
3. Finish as in step 8.

1. `event stage.entered {stage: "pr"}`.
2. **Push:** `git push -u origin <branch>`, exactly. The mod refuses any other push.
3. **Write `run_dir/pr-body.md`** in `config.languages.pr`:
   - **Summary**;
   - **Changes**, item by item;
   - **Acceptance scenarios covered**;
   - **Tests**: the commands and their results;
   - **Screenshots**: their local paths and captions, saying they are local files;
   - **Assumptions and decisions**;
   - **Risks and notes**;
   - `Closes #<n>`, when the source is an issue.

   Also follow the repository's PR template (`.github/pull_request_template.md`) and its CLAUDE.md rules for PRs. No attribution lines.
4. **Open it:** `gh pr create --base <base> --head <branch> --title "<title in the repository's style>" --body-file run_dir/pr-body.md`, adding `--draft` when `config.pr.draft` is set. Then record `pr.opened {url, number, draft}`.
5. **CI**, when `config.pr.wait_ci` is set:
   1. `ci.updated {state: "pending"}`.
   2. Run `gh pr checks <number> --watch --fail-fast` as a background Bash command, then end the turn. The mod shows `waiting_ci`.
   3. When its notification arrives:
      - **Green**: `ci.updated {state: "passing"}`.
      - **Red**:
        1. `ci.updated {state: "failing"}`.
        2. Read `gh run view <id> --log-failed`.
        3. Fix it through the implement loop (implementer, verifier, commit).
        4. Push, and watch again.
      - The fixes are limited to `budgets.ci_fix_attempts`. Past that, record `blocked` and ask; in `full`, finish with `outcome: "failed"` and a summary of what still fails.
   4. A repository with no checks counts as passing, with a note.
   5. A suite left to CI (`config.tests.suite_runs` or `e2e_runs` set to `ci`) is proven here: a red check in it is fixed like any other.
6. **Ready:** when the PR is a draft and CI is green, `gh pr ready <number>` and `pr.ready`.
7. `event stage.completed {stage: "pr"}`.
8. **Finish.**
   1. Write `run_dir/summary.md`:
      - what was delivered;
      - the PR link;
      - the assumptions and decisions;
      - the open items;
      - the time per stage, from `get` scope `run`.
   2. `event run.finished {outcome: "done", summary: "<one line>"}`.
   3. Keep the worktree: the person reviews and removes it.
   4. The last message: five lines at most, with the PR link and the path to `summary.md`.
